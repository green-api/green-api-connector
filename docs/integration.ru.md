# Интеграция расширения в ваш продукт

[English version](integration.md)

Тестовая страница позволяет проверить команды и ответы между страницей и расширением.

> Для авторизации через значок расширения тестовая страница не нужна.

1. В браузере отключите обычную версию расширения и установите тестовую: `test/chrome/` или `test/firefox/manifest.json` из релиза. В названии есть `(debug - не для публикации)`.
2. В Chrome в разделе **«Подробнее»** тестового расширения включите **«Разрешить доступ к URL файлов»**.
3. Откройте `test/test-page.html` в том же браузере и профиле. Дождитесь статуса **«Расширение подключено и готово к работе»**; в журнале должен появиться входящий ответ `CONNECTOR_READY`.
4. Введите данные тестового инстанса и нажмите **«Начать авторизацию»**. Пройдите вход в WhatsApp и дождитесь `IMPORT_SENT` либо проверьте причину в `IMPORT_ERROR`. Если заполнены и `idInstance`, и `apiTokenInstance`, они имеют приоритет над полем **«Полный URL endpoint»**; чтобы использовать свой endpoint, очистите оба поля.
5. После проверки удалите тестовую сборку и установите обычную из `chrome/` или `firefox/`.

Тестовая сборка доверяет локальным страницам (`file://` и `http://localhost`). **Не публикуйте и не распространяйте `test/`**. Для публикации используйте только обычные сборки или соответствующие ZIP-архивы. Вручную включать `DEV_MODE` для этой проверки не требуется.

Простой пример интеграции на HTML и JavaScript находится в [`example/index.html`](../example/index.html): он отправляет те же команды и показывает ответы расширения. При локальном открытии ему тоже нужна тестовая сборка.

## Как работать с расширением

Передача данных между страницей и расширением происходит через [события `message`](https://developer.mozilla.org/en-US/docs/Web/API/Window/message_event).

### Исходящие запросы

Пример payload запроса:

```json
{ "target": "green-api-connector", "type": "PING" }
```

- `target` - маркер расширения. Указывается в [config.ts](../src/shared/config.ts) через переменную `CONNECTOR_SOURCE`
- `type` - тип исходящего запроса

Возможные значения поля `type`:

- `PING` - проверка что расширение установлено и доступно на странице
- `START_IMPORT` - запустить процесс авторизации. Необходимо добавить URL endpoint в поле `url` куда будут отправлены [данные авторизации](#как-использовать-данные-авторизации)
- `START_PASSKEY_IMPORT` - тоже самое что и `START_IMPORT` (обратная совместимость)
- `CLEAR_AND_CONTINUE` - очистить данные, если они существуют и запустить процесс авторизации. Можно использовать если был получен [ответ](#входящие-запросы) с типом `EXISTING_SESSION`, чтобы принудительно начать процесс авторизации
- `KEEP_AND_CONTINUE` - использовать уже имеющуюся сессию, не очищая данные. Отправляется в ответ на событие `EXISTING_SESSION` как альтернатива `CLEAR_AND_CONTINUE`: сработает только одно из двух
- `CANCEL_IMPORT` - отменить процесс авторизации. Если ранее было открыто окно с Web версией, оно будет закрыто

Пример запроса в коде:

```js
window.postMessage({
    target: "green-api-connector",
    type: "START_IMPORT",
    url: "https://api.green-api.com/waInstance{{idInstance}}/setAuthCreds/{{apiTokenInstance}}",
  }, "*");
```

### Входящие запросы

Для получения событий необходимо подписаться на события `message`.

Чтобы обрабатывать только события от расширения можно реализовать фильтр по маркеру расширения, например:

```js
window.addEventListener("message", (event) => {
  if (event.source !== window || event.data?.source !== "green-api-connector") {
    return;
  }
  // логика обработки события от расширения
});
```

Пример payload входящего запроса:

```json
{ 
  "source": "green-api-connector", 
  "type": "CONNECTOR_READY" 
}
```

- `source` - маркер расширения
- `type` - тип ответа

Возможные значения поля `type`:

- `CONNECTOR_READY` - ответ на PING. Также отправляется при успешной активации на странице
- `IMPORT_SENT` - успешная отправка данных на указанный в `url` endpoint. Имеет дополнительные поля `name` и `number`.
- `EXISTING_SESSION` - уже есть вход в аккаунт. Данные не были отправлены на endpoint
- `IMPORT_ERROR` - ошибка в процессе синхронизации. Причина указана в дополнительном поле `reason`:
  - `import_already_in_progress` - процесс авторизации уже запущен
  - `tab_closed` - вкладка для авторизации была закрыта до завершения авторизации
  - `unexpected_error` - произошла непредвиденная ошибка во время процесса авторизации
  - `network` - не удалось отправить данные на указанный в `url` endpoint
  - `http_error` - сервер ответил ошибкой. В этом случае в сообщении есть дополнительное поле `httpStatus` с кодом ответа
  - `timeout` - данные авторизации не появились за отведённое время

## Как использовать данные авторизации

Для авторизации на инстансе необходимо при запросе `START_IMPORT` указать url в формате:

```
https://api.green-api.com/waInstance{{idInstance}}/setAuthCreds/{{apiTokenInstance}}
```

- `{{idInstance}}` - номер инстанса из личного кабинета
- `{{apiTokenInstance}}` - токен инстанса из личного кабинета

Например:

```js
window.postMessage(
  {
    target: "green-api-connector",
    type: "START_IMPORT",
    url: "https://api.green-api.com/waInstance110501234567/setAuthCreds/Jg9ktxJ5d7pfWVT9Whar9qxmVVPMLN4d49C8nmpbjXyNeYq54b",
  },
  "*",
);
```

При использовании своего backend сервера необходимо проксировать данные полученные от расширения на нужный инстанс.

## Выбор мессенджера на этапе сборки

Логика, специфичная для конкретного мессенджера (например, WhatsApp Web), лежит в `src/packages/<name>/` и выбирается на этапе сборки через переменную окружения `MESSENGER`:

- `npm run build` - собирает расширение с мессенджером по умолчанию (`whatsapp`)
- `npm run build:whatsapp` - явно собирает расширение с мессенджером `whatsapp`

## Как кастомизировать расширение

### Конфигурация

Для создания расширения с вашим брендом (логотип, название, описание, цвета) воспользуйтесь конструктором: бренд сохраняется в папку `branding/` и применяется при сборке.  

Команда запуска конструктора  
```bash
npm run brand-editor -- --lang ru
```

Технические настройки расширения задаются в файле [`src/shared/config.ts`](../src/shared/config.ts)

- `CONNECTOR_SOURCE` - маркер используемый при отправке запросов и фильтрации входящих запросов
- `TRUSTED_DOMAINS` - домены на которых расширение будет активно. White label добавляет свои в конструкторе («Доверенные домены» -> `trustedDomains` в `branding/brand.json`). 
> Например при указании `green-api.com` расширение будет активно и на странице `console.green-api.com`.
- `DEV_MODE` - позволяет работать расширению на `http://localhost` и из открытого в браузере HTML файла. Выключить при публикации расширения.
