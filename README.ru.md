# GREEN-API Connector

[English Version](README.md)   

Расширение помогает получить данные для авторизации WhatsApp инстанса, когда нет возможности совершить авторизацию через стандартные способы. Например, когда вход возможен только через технологию Passkey. 

## Как работает расширение?

Расширение открывает отдельное окно WhatsApp Web для прохождения авторизации, после чего отправляет данные авторизации аккаунта на заданный в [запросе](docs/integration.ru.md#исходящие-запросы) endpoint.

# Быстрый старт

Вы можете использовать ИИ агента для упрощения работы с репозиторием, отправьте агенту ссылку на репозиторий и попросите его помочь собрать расширение.

#### При работе с расширением, доступно два сценария.  
> Требуется [Node.js](https://nodejs.org) версии 18 или новее

### 1. Сборка приложения GREEN-API

Чтобы получить расширение со стандартным названием, логотипом и цветами GREEN-API, выполните:

```bash
npm run release -- --lang ru --default-brand
```

Скрипт установит недостающие зависимости и создаст папку `release/<name>-<version>/`. Параметр `--default-brand` позволяет собрать стандартное расширение.

После сборки установите расширение [в браузере](docs/install.browser.ru.md) или отправьте на публикацию в [Chrome Web Store](docs/publishing.chrome.ru.md), [Firefox Add-ons](docs/publishing.firefox.ru.md).

### 2. Создание собственного приложения «White label»

В режиме редактора вы можете загрузить свой логотип, указать название и описание на русском и английском, выбрать цвета и сразу увидеть, как будет выглядеть расширение. Рекомендуем работать в своём репозитории (сделать форк оригинального репозитория): бренд хранится отдельно, поэтому в будущем проще получать обновления GREEN-API.

Запустите редактор:

```bash
npm run brand-editor -- --lang ru
```

В браузере откроется локальная страница редактора. Если она не открылась автоматически, перейдите по URL из терминала.

1. Если показана кнопка **«Установить зависимости»**, нажмите её и дождитесь загрузки полного редактора.
2. Загрузите логотип (рекомендуется квадратный PNG или SVG размером 512×512), заполните требуемые поля описания, выберите основной цвет. Если будете публиковать расширение в Firefox Add-ons, укажите свой **Firefox ID** - уникальный ID дополнения в одном из форматов - `connector@your-company.com` или `@connector`. Если авторизацию будет запускать ваш собственный сайт, укажите его домен в поле **«Доверенные домены»** (например, `partner.com`, вместе с поддоменами; сайты GREEN-API доверенные всегда) - до первой публикации.
3. Нажмите **«Сохранить»**. Редактор запишет бренд в папку `branding/`
4. Нажмите **«Собрать расширение»** и дождитесь завершения. Редактор покажет путь к релизу и кнопку **«Открыть папку с расширением»**.
5. Закройте вкладку редактора после сборки — локальный сервер завершит работу.

После сборки установите расширение [в браузере](docs/install.browser.ru.md) или отправьте на публикацию в [Chrome Web Store](docs/publishing.chrome.ru.md), [Firefox Add-ons](docs/publishing.firefox.ru.md).

### Работа с релизной сборкой

После сборки расширения будет доступен набор файлов: 

```text
release/
└── <имя_расширения>/
    ├── <имя_расширения>-chrome.zip - архив с расширением для публикации в Chrome Web Store
    ├── <имя_расширения>-firefox.zip - архив с расширением для публикации в Firefox Add-ons
    ├── chrome/ - распакованное расширение для Chrome (установка в браузере в режиме разработчика)
    ├── firefox/ - распакованное расширение для Firefox (установка в браузере в режиме разработчика)
    ├── preview.html - страница с превью готового расширения
    ├── README.txt - инструкция к релизу
    └── test/ - папка для работы с расширением в режиме отладки (для разработчика)
        ├── chrome/
        ├── firefox/
        └── test-page.html
```

Отладочные версии из `test/chrome/` и `test/firefox/` имеют приписку `(debug - не для публикации)` в названии и описание «Расширение собрано в режиме отладки. Внимание! Сборка не для публикации.». Это позволяет отличить их от обычных версий в списке расширений браузера.

Проверка команд и ответов через тестовую страницу описана в отдельной [инструкции по интеграции расширения в ваш продукт White label](docs/integration.ru.md).

## Бренд

Для своего логотипа, названия, описания и цветов используйте редактор из сценария **«Создание собственного приложения „White label“»** выше.   
Бренд хранится только в `branding/` и применяется при сборке поверх стандартного оформления GREEN-API. Файлы `public/icons`, `public/_locales`, `src/shared/theme.css` и заголовки HTML вручную менять не требуется.

Посмотреть сохранённый бренд после сборки расширения можно в файле `release/<имя_расширения>/preview.html`
